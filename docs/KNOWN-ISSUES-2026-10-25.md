## 明细

### 1. `get_trading_calendar` 深交所官方源 404

- **现象**：调用即报 `All sources for 'trading_calendar' failed: szse_official: HTTPError: HTTP Error 404: Not Found`（2026-10-25 20:34 实测）。
- **根因推测**：深交所官网接口路径/反爬策略变更，`szse_official` 适配器未跟进；无备用源兜底。
- **影响**：交易日历判定不可用。当前早盘准备/盘后复盘/周末复盘均已写降级链（financial_calendar 佐证 + WebSearch + 行情探针），但多任务各跑一遍浪费。
- **修复方向**：① 修复/更换 szse 源（或改用交易所 API/akshare `tool_trade_date_hist_sina`）；② 增加 2 级备用源（sina 历史 + 本地缓存表）；③ calendar 结果按月缓存，减少外部依赖。

### 2. `get_valuation_metrics` datetime 比较错误（任何股票均失败）

- **现象**：任意 symbol 报 `获取估值指标失败 (600170): '<' not supported between instances of 'datetime.date' and 'str'`（4 只底仓全部复现）。
- **根因推测**：返回序列排序/过滤时把 `datetime.date` 与字符串日期直接比较，典型为某数据源返回日期类型不一致（str vs date）未归一化。
- **影响**：🔴 个股 PE/PB/PS 历史与分位完全不可用；周末复盘底仓估值分位只能标暂缺。
- **修复方向**：定位排序/切片处的日期归一化（统一 `pd.to_datetime`），补一条 600170 的回归测试。

### 3. `search_news` Timestamp 不可 JSON 序列化

- **现象**：关键词「周末 重大 政策 利好 利空」报 `搜索新闻失败: Object of type Timestamp is not JSON serializable`（2026-10-25 实测）；同类工具（get_telegraph_news）正常。
- **根因推测**：结果集中混入 pandas Timestamp 对象（百度交易提醒/期货新闻子源），聚合层未做 `json.dumps(default=str)` 或 to_datetime 归一。
- **影响**：🔴 定向新闻搜索不可用，自动化降级到 WebSearch，信息时效与精确度下降。
- **修复方向**：聚合出口统一序列化护栏（default=str 或显式 astype(str)）；子源逐个排查补测试。

### 4. `get_historical_price` 指数代码静默错取个股 ⚠️ 最危险

- **现象**：传 `symbol="sh000001"`（上证指数意图），返回 `"symbol": "000001"` 的**平安银行**周线数据（2026-10-25 实测，source=eltdx）。无报错、无标记——**静默数据错误**。
- **根因推测**：symbol 归一化剥离 `sh/sz` 前缀后按 A 股个股路由，指数（000001.SH / 399001.SZ / 399006.SZ）无独立路由分支。
- **影响**：🔴 自动化若按提示词传指数代码，拿到的是个股数据且**无法从返回结构察觉**——已导致 2026-10-25 周末复盘周涨跌幅差点用错数据（人工发现）。比报错严重得多。
- **修复方向**：① 路由层增加指数代码白名单（000001→上证指数 or 报错拒绝，二选一，倾向后者+提示改用专用指数工具）；② 新增 `get_index_kline` 专用工具；③ 短期在工具 docstring 加"不支持指数"硬警告。
- **提示词层已固化**：三任务提示词均禁用本工具取指数，改 WebSearch 两源交叉。

### 5. `get_board_sentiment` 底层要求 date 参数，WB schema 不放行

- **现象**：无参调用报 `fetch_limit_up_board_em 必须传 date 参数（YYYYMMDD）`；但 MCP schema `additionalProperties: false` 且 properties 无 date——调用方**无法传参**，死锁。
- **根因推测**：东财接口 `fetch_limit_up_board_em` 上游变更为必传 date，tradex-hub 的 schema 定义未同步更新（schema 仍声明无参）。
- **影响**：🟡 打板情绪（炸板率/连板梯队/晋级率/平均溢价）不可用；自动化用 get_market_sentiment + get_limit_up_insight 替代（题材频率可覆盖大半）。
- **修复方向**：schema 加 `date: YYYYMMDD（默认今日）`；或服务端默认补当日日期。东财接口一变就断，建议该适配器加参数容错。

### 6. `get_realtime_quote` 返回不含 PE/PB

- **现象**：返回字段仅价格/量额/内外盘，无市盈率/市净率（腾讯子源 `pe` 字段恒空）。
- **根因推测**：腾讯 qt.gtimg.cn 返回串里有估值位（第 39/46 位），解析层未映射。
- **影响**：🟢 估值只能绕道 Wind CLI 或标暂缺。
- **修复方向**：解析层补 pe/pb 字段映射（低成本高收益）。

### 7. CLI `data_router.py kline` 依赖 eltdx 包未安装

- **现象**：`data_router.py kline` 报 `"error": "eltdx 包未安装"`（2026-10-25 实测，managed python 环境）。
- **根因推测**：kline 命令 import 本地 eltdx 包，但该环境未装；而 MCP 网关侧 `eltdx_get_kline` 正常（网关环境有包）——**两套运行环境的依赖不一致**。
- **影响**：🟢 CLI K线不可用；MCP 侧可替代，影响有限。
- **修复方向**：CLI 环境补装 eltdx（与网关同版本），或 kline 命令降级转发到网关；`pyproject.toml` 声明依赖防漂移。

### 8. stdio 并发限制（历史已知 · 待架构级解决）

- **现象**：tradex MCP 并发 >3 时本地 stdio 服务挂死（错误码 -32001）。2026-09 盘后复盘 v3.6 根因修复后以"强制串行/≤3 并发"规避。
- **根因推测**：stdio 传输层或网关并发模型瓶颈。
- **影响**：🟡 自动化全链路被迫串行，采集耗时受限（早盘选股 L2 精算 80 只的时间预算压力主要来自此处）。
- **修复方向**：专项重构时的核心议题——评估 streamable-http 传输下并发安全（客户端已用 streamable-http，网关内部是否仍串行待查）；或引入请求队列。

### 9. 工具数文档口径漂移

- **现象**：README/提示词多处写"129 个工具"，网关 health 实报 **168**。
- **影响**：🟢 文档可信度（新机器部署核对时会困惑）。
- **修复方向**：README 改为动态表述（"以 /health 返回为准"）或构建时自动生成工具清单；提示词真源同步清理具体数字。
